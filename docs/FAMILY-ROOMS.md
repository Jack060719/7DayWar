# 家庭連線候選：玩法與架設

本文件對應 **LD-STAGE3-20261011-02**（2026-10-11）。目前已實作家庭房間，尚未選定託管平台、購買服務或發布網站。Windows Chrome 的驗證範圍見 [TESTING.md](TESTING.md)；Android／iPhone 與十支手機仍待實測。

## 電腦要一直開著嗎？

房主是其中一支手機，負責共同怪物與戰鬥結算。遊戲檔案和配對服務則需要有人提供：

| 部分 | 工作 | 本版存放位置 |
| --- | --- | --- |
| 遊戲網站 | 讓瀏覽器下載程式、美術與音訊 | 只發布 `dist/` |
| 配對服務 | 建立房號，協助手機建立 WebRTC 連線 | 獨立執行 `portable/signaling.mjs` |
| 房主手機 | 計算共同世界，傳送畫面及個人成果 | 房主瀏覽器，遊戲需保持前景 |
| 每人的存檔 | 保存自己的角色 | 各自瀏覽器的 IndexedDB |

若前兩項仍由你的電腦提供，電腦就需要保持開機、連網並運行服務。將兩項都放到持續運作的網路服務後，遊玩便不需要你的電腦開著；目前尚未部署。

GitHub Pages 可以放靜態遊戲，配對 Node 程式須另有執行環境。這是服務種類的差別，並不表示本次已選用 GitHub Pages。參見 [GitHub Pages 官方說明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

## 已確認的玩法

- 每支手機保存最多四名角色，可分圖自動練功或同圖組隊；家庭房只帶選中的一人，其餘本機角色暫停，離房後繼續。平時各自玩各自的角色；聚在一起時連同一個 Wi-Fi，允許使用網際網路下載遊戲及配對。常態 2–3 人，最多 10 人含房主。
- 每次開房建立新的共同世界，大家從房主的家鄉城鎮附近開始。帶入自己的角色成長、裝備、物品、任務及寵物；不複製任何人的舊怪物世界。
- 每隻怪分別記錄參戰者。本人或同伴實際發動攻擊即算參戰，包含未命中；實際補到既有參戰者的血也算，包含持續治療及後續治療支援者。只有選中目標、站在旁邊或補血但沒有恢復 HP 不會因此取得資格。
- 合格參戰者均分總經驗，整數零頭輪流分配。普通怪每份掉落堆隨機分給一人；Boss 的全隊掉落池也分配給參戰者，並確保每人至少有金幣或一般戰利品，稀有裝備不保證。參戰後死亡或跨圖仍保留該怪資格，離房則清除；不另加距離限制。掉落留在怪物死亡地圖，由獲分配者拾取，背包滿不改送別人。
- 家庭房人數倍率：1 人 ×1、2 人 ×1.5、3 人 ×2.5、4 人 ×3.5、5 人 ×4.5、6–10 人 ×5。怪物首次開戰時以同圖房員數鎖定，套用血量、攻擊、物理防禦及全隊經驗／掉落總量，直到該怪死亡不重算。魔防、命中及速度不增加；物理防禦依既有 AC 方向加強，並非直接把 AC 數字乘大。
- 個人任務、商店消費、裝備及消耗仍各自結算。離房回到各自進房前的地圖與位置，保留已保存成果；單人世界與原本時鐘不跟著房間時間前進，效果剩餘時間會換回單人時鐘。
- 未拾取的掉落、房間怪物與房間召喚物不帶回單人世界。進房前已有的單人召喚物留在原世界，返回時還原。
- 房主離開、失聯或遊戲長時間停止執行，房間結束，不轉移房主。切到背景會嘗試保存並離房；手機直接關閉或被系統終止時，只能依已成功保存的進度恢復。

目前是可信任家人共玩的候選，沒有帳號服務、雲端角色同步或公開競技防作弊。房號只提供給要加入的家人。

## 如何開房與加入

1. 各自在自己的瀏覽器準備角色。先完成死亡復活、施法、航行或療養，並保留自己的 JSON 備份。
2. 用 HTTPS 遊戲網址開啟遊戲。電腦開發測試可用 `http://localhost`；手機用一般 `http://電腦IP` 開頁只能測試單人，家庭連線入口會要求安全來源。
3. 在「旅人選單 → 家庭連線」填入管理者提供的「配對服務網址」。同站反向代理通常填 `/signal`；分開託管時填完整的 `https://配對服務網域/signal`。
4. 房主按「建立房間」，把 12 位房號交給家人。其他人填相同配對網址與房號，再按「加入房間」。
5. 確認名單與保存狀態，保持遊戲在前景。結束時使用「保存並離開房間」。

網址是角色儲存來源的一部分。更換 HTTP／HTTPS、網域、IP 或連接埠，原角色不會自動出現在新來源；先從舊網址匯出再到新網址匯入。見 [SAVE_SAFETY.md](SAVE_SAFETY.md)。

## 本機開發測試

以下命令在儲存庫根目錄的兩個終端機分別執行，不需要 npm 安裝：

~~~sh
node portable/server.mjs --root ../dist --port 8080
~~~

~~~sh
node portable/signaling.mjs --port 8788 --origin http://localhost:8080
~~~

瀏覽器開 `http://localhost:8080/full/`，配對網址填 `http://localhost:8788/signal`。兩個服務都預設只監聽 `127.0.0.1`；終端機必須保持開啟。兩個獨立瀏覽器設定檔可測兩個角色，同一儲存來源的普通分頁仍受單一寫入者保護。

`--origin` 必須完整符合**遊戲頁面**的來源：通訊協定、主機及非預設連接埠；不要加 `/full/`、結尾斜線或 `*`。例如要同時允許本機兩種網址：

~~~sh
node portable/signaling.mjs --port 8788 --origin http://localhost:8080 --origin http://127.0.0.1:8080
~~~

單獨打開配對網址並不會出現遊戲頁面；它提供 `/signal/rooms` API。唯讀靜態伺服器也不會自動轉發 `/signal`。

## 後續託管需要配置的內容

這是部署契約，尚未替任何平台開通、修改公開權限、設定防火牆或發布。

1. **靜態網站：** 發布根目錄只選 `dist/`，完整入口為 `/full/`。保留相對路徑、檔名大小寫、模組 MIME 及音訊素材，不公開儲存庫、fixture、備份或玩家資料。
2. **配對程序：** 在可持續運行 Node 的環境啟動下列命令，把範例網域換成實際遊戲來源：
   
   ~~~sh
   node portable/signaling.mjs --port 8788 --origin https://game.example.com
   ~~~

3. **HTTPS 入口：** 由部署環境提供有效 HTTPS。將公開的 `/signal/` 路徑原樣轉發到 `http://127.0.0.1:8788/signal/`，保留路徑、查詢字串、`Origin`、`Authorization` 及 `Content-Type`；允許 GET、POST、OPTIONS，不快取回應。這裡是一般 HTTP 輪詢 API，不是 WebSocket 服務。
4. **遊戲與配對分站：** 若遊戲在 `https://game.example.com/full/`、配對在 `https://pair.example.com/signal`，仍設定 `--origin https://game.example.com`；遊戲內填後者完整網址。HTTPS 遊戲不能連 HTTP 配對服務。GitHub Pages 之類只有靜態託管的網站不能直接提供本專案的 `/signal` API。
5. **監聽介面：** 同機 HTTPS 代理使用 localhost 預設即可。只有部署環境明確需要由另一個介面連入時，才加 `--lan`，例如容器的入口代理；它會監聽 `0.0.0.0`，不會自動取得 HTTPS 或設定防火牆。
6. **程序生命週期：** 配對資料只在單一程序記憶體中。停止、重新啟動或換一個沒有同一房間資料的程序都會使房間結束；目前沒有跨程序共用房間資料。部署更新前先讓家人保存離房。
7. **部署後驗收：** 先用兩個獨立瀏覽器確認開房、加入、保存及正常／突然中斷，再用 Android 與 iPhone 在同一 Wi-Fi 實測。最後驗收常態 2–3 人及上限 10 人的戰鬥、前後景、長時間載入及恢復，不能以桌面多分頁代替。

配對服務預設最多 50 個房間、單房最多 10 人，房主心跳逾 30 秒或單房存續超過 8 小時會清除房間。這些是目前程式限制。配對持續不可用時，客戶端也會結束房間，不能將它當成只在開房時使用的一次性服務。

## 保存與故障界線

房主約每 100 ms 推進模擬、每 250 ms 發布畫面，約每 2 秒送出個人成果 checkpoint。融合預備／提交、技能突破、附魔、寵物升級／繁殖／背包操作另要求立即保存；友方變身的接受確認涵蓋相關角色。交易須先保存雙方暫鎖物品，再由房主保存完成決定，最後保存雙方成果。checkpoint 在各人自己的 IndexedDB 成功寫入後才算已保存，畫面已顯示的動作不等於已落盤。

正常離房會嘗試做最後保存；突然中斷只保留最後成功保存的 checkpoint，無法承諾最後兩秒一定完整。重新開啟若發現上次房間標記，會先顯示「上次連線已結束」，保留確認成果，待按「繼續單人遊戲」後回到原單人位置；不把未確認的房內時間當成離線狩獵再算一次。

WebRTC 的每則完整訊息上限是 **4 MiB**；傳輸會分段並限制排隊量。個人歷史世界保留在各自手機，不放入加入／成果訊息；成果寫入前取回當次進房前的完整世界，仍核對角色、原位置、時鐘與 RNG。背包或其他必要角色資料若仍超限，會拒絕傳送。配對 HTTP 的個別請求上限另為 32 KiB，內容是配對資料，並不接收角色存檔。

交易在雙方確認前中斷會取消；已開始雙方保存時中斷，相關物品暫鎖，重新連回原房主角色後依保存決定完成或退回。請保留原房主的角色與交易記錄；換一名角色開房無法代替原房主核對。

目前未配置 STUN／TURN 中繼。網際網路協助取得遊戲及交換連線資料，戰鬥使用手機與房主之間的 WebRTC 通道。同一 Wi-Fi 若啟用訪客隔離或裝置隔離，仍可能連不上；這版不承諾跨不同網路或無網際網路的完全離線開房。
