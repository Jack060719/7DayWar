# Paired body artwork processing

The new halves are original imagegen artwork, not a procedural shield overlay. The original full-body halves remain unchanged. Raw images, exact prompts, edits and per-action provenance live in this directory. Runtime copies are under `dist/full/art/shield-pairs/` only after a complete six-action bundle has been inspected.

The skill's Python image helpers were unavailable in this environment. The documented alternative uses isolated native Chromium Canvas through `tests/helpers/browser.mjs` for deterministic decoding, transparent cropping, translation, resampling and WebP encoding. It does not draw replacement character artwork. Set `BROWSER_BINARY` to an available Chrome binary; the local sandbox fixture additionally used `BROWSER_NO_SANDBOX=1`.

1. `build-shield-pairs.mjs` creates source references from existing runtime strips. Direction rows are S, SW, W, NW, N, NE, E, SE; each cell is 192 square, with original durations and anchors.
2. `process-shield-pair.mjs <job.json>` extracts whole bodies. The component mode labels every source nonzero-alpha pixel to exactly one body, preserving curved transparent seams where rectangular row crops would cut raised weapons. It uses one accepted idle scale profile per bundle; later actions only convert that same scale for the raw sheet resolution. Body positioning is translation only. Manually inspected boot/body contact points may override the automatic lower-alpha-band estimator, with coordinates and reason in the job.
3. Cleanup is limited to documented alpha-1 background noise: detached alpha-1-only components, or alpha-1 pixels at least three pixels from every alpha >= 2 pixel. The latter keeps the entire two-pixel antialias band. Every original alpha >= 2 pixel remains byte-identical. Removal counts, locations, bounds and hashes are recorded. This is not a relaxed edge threshold: any nonzero output alpha touching a cell edge still fails.
4. `review-shield-staging.mjs <staged-action-directory>` independently decodes PNG/WebP, compares alpha and durations, verifies protected pixels, and writes each direction's source/generated comparison plus an unscaled gray full-action sheet. It reports the automatic foot-band metric separately; that metric is not anatomical for fallen poses or low weapon tips.
5. `prepare-shield-edit.mjs <staged-action-directory> <direction> [zero-based-frame] [--padding=64|--padding=128]` creates a direction/single-frame edit guide with one uniform raw-cell-derived scale. Padding adds transparent margins without resizing the body. Its JSON records the inverse transform.
6. `reinsert-shield-edit.mjs <contract.json> <edited.png> <new-raw.png>` validates the original hash, applies the inverse transform and rejects edited alpha outside the assigned source region. Unselected pixels must remain unchanged. It also supports the single-frame square-pad contract; fractional pads are inverse-translated by Canvas before integer pixel copying. Keep rejected attempts and never overwrite the original raw file.
7. `promote-shield-pair.mjs <runtime-job.json>` validates six reviewed actions, geometry, codec, raw hashes and unchanged timings, copies the 48 strips, and builds a runtime manifest. It does not mark phone acceptance. A paired stance uses a unique consumer ID for each shield half so cached frames cannot leak across equipment changes. Contact/release timing and measured projectile origins are presentation metadata; no damage, game state or RNG is changed.

Staging geometry, semantic inspection, native Canvas scenes, UI interaction and real-phone acceptance are separate gates. Do not label an entire action accepted from only its first frame. Shared scale cannot conceal anatomy drift; inspect head/torso/weapon proportions as well as numerical silhouette height. Natural far-arm occlusion and known repeated gait poses must be explicitly recorded.
