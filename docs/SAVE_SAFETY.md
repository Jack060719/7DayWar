# 存檔、升級與回退

角色保存在每個瀏覽器自己的 IndexedDB。靜態伺服器與 GitHub 資料夾不保存角色；交付包只能包含程式與合成測試資料，不能包含玩家真實存檔。

## 升級前保留兩樣東西

1. 在舊程式匯出原始 JSON，保留未修改的檔案。
2. 保留與該 JSON 相配的舊版完整程式包，以及版本或檔案雜湊紀錄。

只留其中之一不足以可靠回退。備份不要加入儲存庫，也不要讓新程式覆蓋唯一舊包。新程式有遷移封存機制，但仍應在升級前自行保留原始備份。

## 回到第二階段

第三階段已加入 `inventory.scrolls`／`storage.scrolls` 等新欄位。舊驗證器可能忽略陣列，顯示通過也可能看不到新版卷軸資產；不可直接把新存檔交給舊程式。

現行候選已有獨立的「恢復 Stage2 並停止」流程，並有受控工作階段與介面測試。操作時：

1. 先備份目前進度。選取真正的升級前 Stage2 JSON，確認匯入預覽允許恢復。
2. 使用「恢復 Stage2 並停止」入口，閱讀確認提示後才確認。它會先封存目前進度，再恢復選定快照；不合併升級後進度，也不補算備份至今的離線時間。
3. 成功後立即關閉所有遊戲分頁、停止伺服器，換回與快照相配的第二階段完整程式，再用原網址開啟。

**停止只作用於目前工作階段；不要重新整理仍在使用新版程式的頁面。** 新版重新載入可能再度遷移。此流程不是在新程式裡永久鎖定第二階段，也不會自動替換程式包。

具有圖鑑／變身契約的真正第二階段快照應走此專用入口，不能與更早的變身升級前回退混用。含第三階段新欄位／物品的狀態不應繞過保護。任何復原失敗都應保留原始備份，不可反覆建立新角覆寫。

目前受控儲存測試涵蓋封存、遷移失敗不覆寫、專用恢復與停止；真實 IndexedDB 中斷／裝置故障仍不是已驗證的承諾。

## 換網址、裝置或瀏覽器

- 從原環境匯出 JSON，到新環境檢查後匯入。網址、IP、通訊協定或連接埠不同就可能使用不同儲存來源。
- 不要長期使用無痕模式；清除網站資料前先備份。
- 本機存檔不自動同步，請定期匯出到自己的安全位置。
- 報錯提供版本、錯誤訊息與合成重現案例，避免提交真實角色檔。

存檔鍵、資料庫與內部格式保留部分 `ashen-covenant` 名稱是相容需求，不應因顯示名稱改變而更名。
